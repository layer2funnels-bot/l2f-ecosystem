# Funnel Mapper: design decisions (V7 stage 1, 13 Nov 2026)

Method: screenshots of the current ecosystem copy (`fm-shots/copy-*`), the result (`fm-shots/after-*`), the V7 screens (`../design/v7/screens/desktop/068–076_fmp_*.jpg`) and prototype (`prototype-source/fmp6.js`, `v7.css`), read against the V7 brief (16), the design system (01 §3, §6), the owner's manager document (§5.8) and V7's design handoff. Each row: what V7 proposed, what the copy had, the problem, the decision and why.

| Area | V7 proposed | Copy before this stage | Issue found | Decision | Why |
|---|---|---|---|---|---|
| Theme | Keep Funnel Mapper's own dark navy + emerald (app identity) | Light, ecosystem blues, emerald removed ("reshape step 1", design 08, never shipped) | Step 1 made Funnel Mapper look unlike the app its users know, and its exports still used the old palette (screen and export differed). Three sources (V7, manager doc "current design approved overall", V7 design handoff "dark navy + emerald approved") agree. | **Original theme restored**, dark by default, **light kept as a choice** (the original had both). | Matches the approved design and the live app; removes the screen/export mismatch; brings back a feature step 1 had removed. |
| Navigation | FM's own sidebar (Home, Clients, Funnels, Templates, Trash, pinned clients, Settings) inside the ecosystem rail | Top tabs under an ecosystem header; sidebar, pinned clients and counts dropped | Working features were lost (pinned clients, counts, Trash entry in the menu). | **Original sidebar restored** with pinned clients and counts. The ecosystem rail arrives with P00 (foundation); Funnel Mapper then sits to its right unchanged. | Preserve functionality; V7 layout. |
| Type and control sizes | One step up: base 13.5 → 14.5, sidebar items 38 px, rows 46 px, buttons 34 px, titles 30 | 13 px base, 32 px buttons | Owner feedback: "everything too small". A blanket zoom would also enlarge the map and change saved layouts. | **Pages and editor panels +1 px text, buttons/inputs/menu rows +2 px**; Tailwind small text 13 / 14.5 px. **Map blocks, lines, frames and notes unchanged.** | Readability without moving anyone's maps; exports stay byte-identical in layout. A first pass also enlarged block labels and truncated names ("WhatsApp follow-…"); those rules were excluded and re-checked (full names again). |
| Editor canvas | Prototype shows plain boxes | Rich blocks (icons, page thumbnails, people counts, frames, leak markers) | The prototype is a simplification, not a design for the editor. | **Real editor kept unchanged.** | Brief 16: "do not change maps, editor, reports, sharing, exports". |
| New client | Dialog with duplicate check "Link to existing" | Form without a duplicate check | Linking on a name match alone could merge two different people. | E-mail exact → the person chooses link or new; name only → shown for review; several matches → must choose; nothing automatic. | Owner rule (13 Nov); data safety. |
| Client service down | Show cached list, queue the creation | – | A queue that creates later can duplicate on retry. | **Refuse and save nothing**, with a plain message. A queue only later, with an idempotency key. | "Never a local-only client" without duplicate risk. |
| Team / workspace settings notice | Notice "managed in Office › Admin" | Pages work | The notice would be untrue today (Funnel Mapper's own team is still the truth until migration, V7 D2). | **Not shown yet**; added when the team data moves. | No misleading text. |
| Brand name | "Funnel Mapper" everywhere users see it | "Funnel Mapper Pro V2" | – | Renamed in UI, page titles, sign-in, e-mails, Launcher, app catalogue. Internal ids (`funnel_mapper_pro`, export format `funnel-mapper-pro`, package names) kept so old exported files still import. | V7 acceptance; no risky id change. |
